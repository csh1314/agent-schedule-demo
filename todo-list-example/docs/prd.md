# Todo List 应用 - 产品需求文档（PRD）

## 1. 项目概述

Todo List 是一个纯前端待办事项管理应用，用于验证多 Agent 协作开发流程。用户可以在浏览器中创建、完成、删除待办事项，并按状态进行筛选。所有数据持久化在浏览器 localStorage 中，无需后端服务。

### 1.1 技术栈

- **架构模式**: C 纯前端
- **框架**: React 18 + TypeScript
- **数据存储**: localStorage
- **构建工具**: Vite
- **包管理**: pnpm
- **测试**: Vitest + React Testing Library

### 1.2 目标用户

需要轻量级待办事项管理的个人用户。用户在单一浏览器中使用，无跨设备同步需求。

## 2. 功能需求

### F-001: 添加待办事项

**描述**: 用户可以通过输入框输入文本，提交后创建一条新的待办事项，默认状态为"未完成"。

**验收标准**:

- **AC-001-1**: 基本添加
  - **Given** 用户处于 Todo List 页面
  - **When** 用户在输入框中输入 "买牛奶" 并按下 Enter 键
  - **Then** 列表底部新增一条内容为 "买牛奶" 的待办事项，状态为未完成，输入框被清空

- **AC-001-2**: 点击按钮添加
  - **Given** 用户在输入框中输入了 "写周报"
  - **When** 用户点击"添加"按钮
  - **Then** 列表底部新增一条内容为 "写周报" 的待办事项，状态为未完成，输入框被清空

- **AC-001-3**: 空内容拦截
  - **Given** 用户处于 Todo List 页面
  - **When** 用户未输入任何内容（或仅输入空格）并按下 Enter 键或点击"添加"按钮
  - **Then** 不创建新的待办事项，列表保持不变

- **AC-001-4**: 前后空格清除
  - **Given** 用户处于 Todo List 页面
  - **When** 用户输入 "  读书  " 并提交
  - **Then** 创建的待办事项内容为 "读书"（前后空格被去除）

### F-002: 标记完成/未完成

**描述**: 用户可以切换待办事项的完成状态。已完成的事项应有视觉区分（如删除线）。

**验收标准**:

- **AC-002-1**: 标记为完成
  - **Given** 列表中存在一条状态为"未完成"的待办事项 "买牛奶"
  - **When** 用户点击该事项的复选框（或点击该事项）
  - **Then** 该事项状态变为"已完成"，文字显示删除线样式

- **AC-002-2**: 取消完成标记
  - **Given** 列表中存在一条状态为"已完成"的待办事项 "买牛奶"
  - **When** 用户再次点击该事项的复选框（或点击该事项）
  - **Then** 该事项状态恢复为"未完成"，删除线样式被移除

### F-003: 删除待办事项

**描述**: 用户可以删除不再需要的待办事项。

**验收标准**:

- **AC-003-1**: 删除单条事项
  - **Given** 列表中存在待办事项 "买牛奶"
  - **When** 用户点击该事项的删除按钮
  - **Then** 该事项从列表中移除，不再显示

- **AC-003-2**: 删除后列表更新
  - **Given** 列表中存在 3 条待办事项
  - **When** 用户删除其中 1 条
  - **Then** 列表中仅剩余 2 条待办事项，顺序不变

### F-004: 按状态筛选

**描述**: 用户可以按"全部"、"已完成"、"未完成"三种状态筛选显示的待办事项。

**验收标准**:

- **AC-004-1**: 默认显示全部
  - **Given** 用户首次打开应用
  - **When** 页面加载完成
  - **Then** 筛选状态为"全部"，显示所有待办事项

- **AC-004-2**: 筛选未完成
  - **Given** 列表中有 2 条未完成和 1 条已完成的待办事项
  - **When** 用户点击"未完成"筛选按钮
  - **Then** 仅显示 2 条未完成的待办事项，已完成的事项不显示

- **AC-004-3**: 筛选已完成
  - **Given** 列表中有 2 条未完成和 1 条已完成的待办事项
  - **When** 用户点击"已完成"筛选按钮
  - **Then** 仅显示 1 条已完成的待办事项，未完成的事项不显示

- **AC-004-4**: 切换回全部
  - **Given** 当前筛选状态为"未完成"
  - **When** 用户点击"全部"筛选按钮
  - **Then** 显示所有待办事项（包括已完成和未完成）

- **AC-004-5**: 筛选状态下的空列表
  - **Given** 列表中所有待办事项均为未完成状态
  - **When** 用户点击"已完成"筛选按钮
  - **Then** 列表为空，显示无匹配事项的提示信息

### F-005: 显示剩余未完成数量

**描述**: 页面实时显示当前未完成待办事项的数量。

**验收标准**:

- **AC-005-1**: 初始状态显示
  - **Given** 用户首次打开应用，列表为空
  - **When** 页面加载完成
  - **Then** 显示 "0 项待完成"

- **AC-005-2**: 添加后计数更新
  - **Given** 当前显示 "0 项待完成"
  - **When** 用户添加一条新的待办事项
  - **Then** 显示 "1 项待完成"

- **AC-005-3**: 完成后计数更新
  - **Given** 当前有 3 条未完成事项，显示 "3 项待完成"
  - **When** 用户标记其中 1 条为已完成
  - **Then** 显示 "2 项待完成"

- **AC-005-4**: 删除后计数更新
  - **Given** 当前有 2 条未完成事项，显示 "2 项待完成"
  - **When** 用户删除其中 1 条未完成事项
  - **Then** 显示 "1 项待完成"

- **AC-005-5**: 删除已完成事项不影响计数
  - **Given** 当前有 2 条未完成事项和 1 条已完成事项，显示 "2 项待完成"
  - **When** 用户删除该已完成事项
  - **Then** 显示仍为 "2 项待完成"

### F-006: 数据持久化（localStorage）

**描述**: 所有待办事项数据保存在 localStorage 中，刷新页面后数据不丢失。

**验收标准**:

- **AC-006-1**: 添加后持久化
  - **Given** 用户添加了 "买牛奶" 待办事项
  - **When** 用户刷新页面
  - **Then** 列表中仍显示 "买牛奶" 待办事项，状态保持不变

- **AC-006-2**: 状态变更后持久化
  - **Given** 用户将 "买牛奶" 标记为已完成
  - **When** 用户刷新页面
  - **Then** "买牛奶" 仍显示为已完成状态（带删除线）

- **AC-006-3**: 删除后持久化
  - **Given** 用户删除了 "买牛奶" 待办事项
  - **When** 用户刷新页面
  - **Then** "买牛奶" 不再出现在列表中

## 3. 非功能需求

### NFR-001: 性能

- 页面首次加载时间（LCP）不超过 2 秒（本地开发环境）
- 添加、删除、切换状态操作响应时间不超过 100ms
- 支持至少 100 条待办事项而无明显性能下降

### NFR-002: 可访问性（Accessibility）

- 所有交互元素（输入框、按钮、复选框）可通过键盘 Tab 键导航
- 输入框支持 Enter 键提交
- 按钮和表单控件具有合适的 `aria-label` 或关联的 `<label>`
- 颜色对比度符合 WCAG 2.1 AA 标准

### NFR-003: 兼容性

- 支持 Chrome、Firefox、Safari、Edge 最新版本
- 支持移动端响应式布局（最小宽度 320px）

### NFR-004: 代码质量

- TypeScript 严格模式（`strict: true`）
- 测试覆盖率：核心业务逻辑（添加、删除、切换状态、筛选、计数）100%
- 组件渲染测试覆盖所有用户交互场景

```typescript
interface Todo {
  id: string;          // 唯一标识，使用 crypto.randomUUID() 或时间戳生成
  text: string;        // 待办事项内容
  completed: boolean;  // 是否已完成

}
```

## 6. 范围外（Out of Scope）

- 待办事项编辑（修改已创建的文本内容）
- 待办事项排序/拖拽
- 多用户/账户系统
- 后端 API / 数据库
- 跨设备数据同步
- 到期日期/提醒功能
- 分类/标签功能
